# Просмотр цифр за прошлую дату

2026-08-02

## Проблема

Все цифры на странице (Должны/Отдали сегодня/Отдали в этом месяце/Разница,
Было/Поступило, категории по методам) считаются от `todayStr()` —
текущей календарной даты. 1 числа месяц меняется, и "Отдали в этом месяце"
у всех строк естественно уходит в 0 — это ожидаемое поведение, не баг,
но раньше посмотреть цифры прошлого дня (например 31 июля) было нельзя:
UI всегда показывает только "сейчас".

Данные для этого уже есть: у каждого расхода есть `date`
([app.js:23](../../../app.js#L23)), балансы по методам хранятся по ключу
`<method>_<date>` ([app.js:24](../../../app.js#L24)). Новых полей/коллекций
не нужно — нужен только режим просмотра существующих данных за выбранный день.

## Решение

Глобальная переменная `viewDate` (по умолчанию `todayStr()`), которую весь
рендер использует вместо жёстко зашитого `todayStr()`. Дата-picker на
странице переключает её.

### UI

- `<input type="date">` рядом с кнопкой "Перейти к новому месяцу"
  ([index.html:46](../../../index.html#L46)). `min` = сегодня−30 дней,
  `max` = сегодня, значение по умолчанию = сегодня.
- Смена даты → `viewDate = <выбранное>`, `renderAll()`.
- Пока `viewDate !== todayStr()`: жёлтая плашка сверху страницы —
  "Просмотр: <дата> — только просмотр" + кнопка "Сегодня" (сброс на
  `todayStr()` и перерисовка). Одна плашка на всю страницу.
- Пикер доступен и обычным (не-админ) пользователям — как и остальная
  страница сейчас, она read-only для них по умолчанию
  (`state.isAdmin`, [app.js:19](../../../app.js#L19)).

### Данные / рендер

`viewDate` подставляется вместо `todayStr()` только в местах **отображения**:

- [app.js:280](../../../app.js#L280), [app.js:457](../../../app.js#L457),
  [app.js:639](../../../app.js#L639), [app.js:749](../../../app.js#L749),
  [app.js:858](../../../app.js#L858) — `const date = todayStr()` →
  `const date = viewDate`.

Формулы (`paidTodayByName`, `paidThisMonthByName`, `monthOf`) не меняются —
они уже принимают дату/месяц параметром. `row.due` — статичное поле, от
даты не зависит, как и сейчас.

Точки **записи** (создание/правка данных, привязанных к конкретному дню)
тоже переключаются на `viewDate` вместо `todayStr()`, иначе правка
"задним числом" запишется в сегодняшний день:

- [app.js:378](../../../app.js#L378) (`addExpense`),
  [app.js:1034-1035](../../../app.js#L1034) (`setWas`/`setIncome`),
  и точки вызова `addSource`/`removeSource`.

Категории уже day-scoped: список "пустеет" на следующий день, потому что
рендер сейчас фильтрует по `date === todayStr()`
(см. коммент [app.js:4-6](../../../app.js#L4)). Замена на `viewDate`
автоматически покажет категории того дня без доп. кода.

`onSnapshot`-обновления продолжают вызывать `renderAll()` как сейчас —
просмотр прошлой даты остаётся стабильным и просто пересчитывается на
актуальный `CACHE` с тем же `viewDate`.

### Гейтинг правок в прошлой дате

Две группы контролов, когда `viewDate !== todayStr()`:

**Жёстко заблокировано** (не привязано к конкретному дню, код не
разблокирует): добавление/редактирование/удаление строки долга,
пометка "долг", комментарий к строке, drag-реордер строк, "Перейти к
новому месяцу", "Исправить Отдали в этом месяце". Управляющие элементы
получают `disabled`/скрываются, пока `viewDate !== todayStr()`.

**Разблокируется кодом `1223`** (тот же код, что и в существующем
`data-fix-month`, [app.js:731-732](../../../app.js#L731)) — данные,
которые реально принадлежат конкретному дню: Было/Поступило, источники
дохода, категории-расходы (добавить/чек/удалить). При попытке действия —
`prompt('Код подтверждения:')`; неверный/пустой код → `alert('Неверный
код')`, действие отменяется. Код спрашивается на каждое действие отдельно
(без отдельного "режима разблокировки" — меньше риска забыть его выключить,
и это уже привычный паттерн в этом коде).

## Вне рамок

- Даты старше 30 дней назад — пикер их не позволяет выбрать.
- Персистентность `viewDate` между перезагрузками страницы — не нужна,
  всегда сброс на сегодня.
- Правка строк долга (`rows`) "задним числом" — не имеет смысла, они не
  day-scoped.
